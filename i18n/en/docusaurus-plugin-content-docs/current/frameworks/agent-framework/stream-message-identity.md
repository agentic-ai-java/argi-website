# Streaming message identity and views

## Baseline and dependencies

This guide covers the independent `io.github.agentic.ai.agent.react.ReActAgent`,
not graph-based `ReactAgent` or Graph streaming. It targets Core
[ef67b8e08](https://github.com/agentic-ai-java/argi/tree/ef67b8e083746899da43c0a056b76b71db9e92ab),
checked on 2026-11-17, including merged [#358](https://github.com/agentic-ai-java/argi/pull/358).
Its source version is `2.1.0-RC2-SNAPSHOT`; this does not imply publication to
Maven Central, and the same SNAPSHOT string does not identify the source.
This page does not replace the historically pinned
[runtime contracts](https://github.com/agentic-ai-java/argi-website/blob/7974c3b40392722557a4404210cfb6cb4a975a16/docs/frameworks/agent-framework/runtime-contracts.md).

The example depends on `io.github.agentic-ai-java:argi-agent-core:2.1.0-RC2-SNAPSHOT`,
bringing neutral ChatClient, Agent and Runtime contracts transitively. No Spring
Boot, Graph, Extensions BOM, provider adapter or API key is needed. Install the
pinned source first.

Explicitly enable model streaming with `ReActAgent.builder(client).streamModel(true).build()`;
subscribe to the `Flow.Publisher<AgentEvent>` from `agent.stream(request, context)`.
This guide covers that explicitly enabled path, not ordinary `call`.

## Consumer rules

| Event | Action |
| --- | --- |
| `AgentEvent.MessageDelta` | Append `text()` under `messageId()`. |
| `AgentEvent.Message` | Replace that key with `message().text()`; do not append again. |
| `AgentEvent.Finished` | Retain `outcome()`; a snapshot does not prove the whole run succeeded. |
| `onError` | Mark the run failed; deltas without a snapshot remain incomplete. |

Deltas `He`, `llo` followed by snapshot `Hello` must display `Hello`, not
`HelloHello`. Structured repair can replace the terminal message under the same
ID again; do not permanently ignore subsequent snapshots with that ID.

```java
if (event instanceof AgentEvent.MessageDelta delta) {
    text.merge(delta.messageId(), delta.text(), String::concat);
} else if (event instanceof AgentEvent.Message message) {
    text.put(message.messageId(), message.message().text());
}
```

This is a text projection only. Retain the full `ChatMessage` when roles, tool
calls or other content matter.

## Identity boundaries and failures

- This baseline uses `model-0`, `model-1`, etc. for model turns and `tool-<callId>`
  for tool results. Use event-supplied IDs; do not parse or manufacture these formats.
- One turn's deltas and snapshot share an ID. Keep turns and tool results separate.
- IDs are invocation-local. A second invocation can start at `model-0` again.
  Create a fresh view per invocation; aggregate with an application-owned invocation
  identifier plus message ID, not session ID alone or message ID alone.
- A textless tool turn can still have a snapshot; a preceding delta is not required.
- Each model turn requires exactly one assistant message; multi-message responses
  are rejected.
- Failure or cancellation may leave deltas without a snapshot. Display them as
  incomplete, not delivered answers. Subscription cancellation does not guarantee
  a terminal callback; track cancellation in the application too.
- This is not a cross-process recovery, replay-deduplication, global-uniqueness
  or provider-ID pass-through guarantee.

## Run the offline example

The website repository's `examples/stream-message-identity/` contains a complete
fake `ChatClient` and message view, with events generated by the real ReAct engine.
Requirements: JDK 17+ and Maven 3.9.1+. In a Core checkout:

```bash
git checkout ef67b8e083746899da43c0a056b76b71db9e92ab
./mvnw -B -pl :argi-agent-core -am install -DskipTests
```

From the website repository root:

```bash
mvn -B -f examples/stream-message-identity/pom.xml compile exec:java
```

Dependency downloads need network access; execution needs neither network nor
credentials. Success prints:

```text
PASS: turn identity, snapshot replacement, invocation isolation, failure projection
```

Failed assertions fail the command without relying on `-ea`.

## Validation mapping and limitations

| Coverage | Offline example check |
| --- | --- |
| No duplicate delta/snapshot text | Split text, replace snapshot, assert final value. |
| Turn/tool isolation | Two model turns and one local tool produce three messages. |
| Invocation isolation | Reuse one agent with two fresh views, allowing `model-0` in both. |
| Partial text on failure | Fail after a delta; retain partial text without a snapshot. |
| Cancellation, repair, textless tool turns | Not repeated here; grounded in pinned upstream tests below. |
